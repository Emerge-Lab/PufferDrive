# ReGentS integration plan

## Goal and scope

Build a deterministic offline workflow that generates adversarial vehicle scenarios, saves them, and compares rule-based (IDM, corridor-IDM, PDM) and learned-policy ego controllers on the same scenarios. C remains authoritative for controller execution, collisions, off-road events, and metrics; PyTorch only optimizes temporary adversary actions. The local paper and `ReGentS/` checkout resolve ambiguous behavior.

Initial scope is one scenario per job, `classic` dynamics, continuous acceleration/target steering, vehicle adversaries, and a frozen logged/IDM/corridor-IDM/PDM/policy ego trajectory within each Torch block. Excluded for now: PPO updates, gradients through the ego, online training integration, jerk dynamics, pedestrians/cyclists, and batched optimization.

## Contracts and invariants

- Loss weights (updated 2026-09-09): use the released ReGentS configuration from `conf/config_scenario_opt.yaml`: ego collision `1.0` (implicit coefficient), background/adversary collision `5.0`, and road/adversary deviation `20.0`. The background cutoff remains `1.25`, now applied in metres to signed box clearance as specified by the paper and inherited KING method. Our corrected road raster makes the deviation term active, unlike the released implementation's defective crop, so its weight has a real effect after the paper's time normalization described below.
- Full-log selection can retain candidates absent from a shorter optimization window. Such scenes retain the full-log candidate mask but return `no_candidate_in_optimization_horizon` without evaluating an undefined ego loss. The pinned map-8/16-transition reactive-IDM fixture now exercises this outcome: moving candidate 15 first becomes valid at transition 33, while prior candidates 20 and 22 are stationary at zero logged speed and are filtered. Such a scene writes no loss-history CSV, because it records no cost history. Map 3 supplies the live real-scenario optimizer regression. The map-7 open-loop replay explicitly disables the speed gate only inside its test fixture because its purpose is to exercise baseline-relative collision accounting with a stationary overlapping actor; production generation retains the gate.
- Candidate filtering (updated 2026-09-07): filter over the complete exported log, independently of the optimization horizon, except for the explicitly configured reconstruction-fidelity gate described below. Exclude ego, non-vehicles, agents with valid-state fraction below 0.5, first-to-last displacement below 0.2 m, maximum absolute logged speed below 0.2 m/s, or rear bearing outside +/-7pi/8 for more than 80% of logged timesteps. The speed gate intentionally departs from released ReGentS: NuPlan parked tracks can accumulate enough localization jitter to pass the displacement-only test and then receive adversarial acceleration. Rear occupancy includes invalid timesteps as in the reference. Exclude collation-only time padding using the scenario's maximum exported trajectory length. Minimum valid-transition gates remain removed; logged ego overlaps are diagnostics only. Valid-transition masking still controls which actions exist. Retain adapter presence/metadata checks and the invalid-ego scene constraint. `minimum_valid_state_fraction` replaces the obsolete valid-transition filter fields; `static_speed_threshold_mps` is restored and recorded explicitly in generation configs. `valid_state_fraction` and peak speed accompany transition diagnostics. Acceleration units are unchanged.
- Off-road start filter (2026-09-09): exclude a candidate whose logged start lies entirely off the drivable raster. An agent that begins off the drivable surface has no lane the optimizer can keep it on, so accelerating it into the ego only manufactures an off-road adversary. The test uses the agent's first *valid* logged state, because storage is zero filled before an agent enters, and its whole footprint (four oriented-box corners plus the center) sampled at the nearest raster pixel, as the off-road cost signature does: lane corridors are rasterized to a nominal lane width, so a vehicle straddling a corridor edge stays eligible. Center-only sampling rejected the sole surviving candidate of the pinned map-8 fixture, whose center sits 1.0 m outside the corridor. `filter_off_road_start` (default true) disables the gate for cohorts whose maps rasterize poorly; the `off_road_start` reason and the per-agent `start_off_road` flag are reported either way. On the pinned NuPlan fixtures the gate removes 8 of 29 pre-filter candidates on map 8 and 2 of 68 on map 7. Existing artifacts must be regenerated to reflect this policy.
- Expert-action reconstruction and fidelity gate (updated 2026-09-08): match Waymax's sequential expert actor rather than estimating independent `logged[t] -> logged[t+1]` transitions. Each solve starts from the preceding PufferDrive prediction, targets `logged[t+1]`, advances through `classic_step`, and carries that complete predicted state into the next solve; a validity-gap run start alone is seeded from the log. Position, heading, speed, scalar residual, and `model_consistent` now describe this actual reconstructed baseline. Candidate selection gates the maximum valid-timestep center-position drift over the optimization horizon, not the fraction of timesteps meeting the diagnostic `1e-4` tolerances. The 250-scenario WOD audit found 2,373 pre-gate candidates in 246 scenes: maximum-drift q50/q75/q90/q95/q99/max were 0.143/0.309/0.686/1.290/4.808/24.243 m, versus 2.660/5.855/11.089/15.771/31.378/89.602 m for the prior independently estimated sequence. The WOD cutoff is 1.0 m, retaining 2,213 candidates and 244 of the 246 pre-gate eligible scenes while rejecting the upper 6.7% actor tail. Strict consistency and maximum scalar residual remain reported but are not selection criteria. The drift gate defaults to infinity for existing NuPlan profiles until their cohort is measured.
- Static-track handling (2026-09-07): measure displacement between an agent's first and last *valid* logged states, deviating from the reference's raw first/last storage samples. State storage is zero filled outside an agent's logged frames, so raw endpoints measured distance to the map origin for every agent entering or leaving mid scene: a parked car absent at t=0 reported tens of metres, while a car absent at both endpoints reported exactly 0 m and was wrongly filtered as static. On `regents_nuplan` the endpoint correction moved candidates 536 -> 572, but still admitted 190 candidates that never exceeded 0.1 m/s. The restored speed gate closes that gap. In the fifth saved gallery scenario, parked agents 3 and 5 have zero logged speed but 0.539 m and 0.294 m endpoint jitter; displacement-only selection let optimization move them 11.924 m and 16.345 m. They are now static, remain replay-controlled, and cannot receive optimized actions. Existing artifacts must be regenerated to reflect this policy.
- Experiment overrides (2026-09-07): `puffer regents` accepts `--experiment-name`/`--exp-name` and `--road-weight`/`--drivable-area-weight`. A named run is written below `<configured-output>/<generation-name>/<experiment-name>`; names are restricted to portable path-segment characters. The road weight must be finite and non-negative, may be zero to disable the differentiable road term, and is applied to the resolved optimizer cost config before worker launch. Both overrides are persisted in artifact source configuration and therefore participate in its source hash. C off-road detection and reporting remain enabled when the loss weight is zero.
- WOD Motion policy profile (2026-09-08): `regents_wod_motion_val_policy` mirrors `regents_wod_motion_val` - same 90-transition horizon, 1.0 m raster, `lr=0.005`, 0.2 m/s stationary gate, 1.0 m reconstruction-drift gate, and `base_max_speed_mps: 40.0` - and differs only in the ego: `sdc_controller: policy`, `dynamics_model: jerk`, zeroed dropout and erratic-driver knobs, and `ego_refresh_interval: 10` rather than 1. The IDM profile can afford a refresh per update; a policy refresh is 90 C steps plus 90 forward passes, so an interval of 1 would cost 45k inferences per scenario. Correctness is unaffected, because a run-ending contact found against a stale ego still forces a refresh and re-evaluates the same iterate; only in-loop reactivity is traded. On an eight-scenario smoke at 30 updates the worst C/Torch error was `5.722e-05` against `4.196e-05` for the IDM profile, both far inside the `5e-4` gate, and cross-evaluation reproduced every recorded collision timestep under each set's own ego (8/8). The WOMD sets show the same non-neutrality as NuPlan: the policy-targeted set scores 0.375 ego collisions against the policy versus 0.250 against IDM and 0.125 against log replay, while the IDM-targeted set scores 0.625 against IDM and 0.250 against both others.
- WOD Motion validation profile (updated 2026-09-08): `regents_wod_motion_val` targets `pufferlib/resources/drive/binaries/wod-motion_val`. WOD logs contain 91 states and encode their nominal 0.1 s sampling interval as approximately 0.099 s. At the user's direction, adapter and inverse-dynamics validation accept an absolute timestep difference up to 1.01 ms while simulation remains at 0.1 s; larger mismatches still fail. The profile uses the full 90-transition horizon with `scenario_length=resample_frequency=91`, logged-SDC replay, the first 250 lexicographically sorted validation binaries, seeds 42 through 291, 24 workers, 500 Adam updates at learning rate `0.005`, the 0.2 m/s stationary-track gate, the 1.0 m sequential reconstruction-drift gate, and a 1.0 m road raster matching the released WOD configuration. Its `base_max_speed_mps` is 40.0, removing the former 20 m/s failure mode and giving headroom above the cohort's ordinary traffic without changing the 20.0 m/s NuPlan/training default. Implausible faster outliers are excluded when their bounded reconstruction breaches the drift gate. This extends offline generation scope to WOD Motion without changing the NuPlan profiles.
- Validity-gap injection parity (updated 2026-09-08): a replay actor can disappear and later resume with a different logged box length. C refreshes its dimensions and `wheelbase = 0.6 * length` at each contiguous ReGentS injection-run start, then holds them for that run. Torch inverse dynamics, curvature conversion, and optimized rollout use the same run-start wheelbase instead of retaining the actor's first-valid wheelbase across every gap. WOD scenarios 22 and 28 exposed this as unrelated-candidate C/Torch errors of 6.95 mm and 76.78 mm; fixed replays measure 0.0064 mm and 0.0172 mm respectively and remain well below the parity gate.
- C/Torch replay tolerance (2026-09-08): use a maximum absolute state-feature error of `5e-4` for the full 90-transition WOD replay while retaining `1e-4` for the shared initial-pose check. At `1e-4`, 52 of 244 candidate-bearing scenarios were rejected solely for 0.103--0.359 mm accumulated x/y differences at timesteps 37--90; all 52 had both a Torch collision and a C-confirmed actionable ego collision. The maximum was `3.586e-4`, so the new gate remains sub-millimetric and accepts those numerically equivalent replays. The reconstruction-fidelity gate remains independently fixed at 1.0 m against the source log.
- Generation-yield reporting (2026-09-07): persist the full-log candidate count, Torch collision verdict, and Torch collision timestep per scenario; the existing collision timestep remains C's first introduced collision. The progress bar and primary success rate use only scenarios with at least one candidate; no-candidate scenes remain in the CSV and overall cohort rate but are reported separately as filtered rather than rejected. The terminal summary exposes the full collision funnel—eligible scene, Torch ego collision, C-confirmed actionable collision, and Torch collision not confirmed by C—with an explicit denominator at every stage. Aggregate C ego, actionable, background-collision, and off-road diagnostics retain the full-cohort denominator.
- Loss/update decision (updated 2026-09-09): use the paper's oriented bounding-box collision distances in metres. Ego is `min_i mean_valid_t d_BB(ego,i,t)`; background is `-min_pair,t min(1.25 m, d_BB(i,j,t))`. `d_BB` is signed so contact is zero and penetration is negative, resolving the paper's `d_BB <= 0` collision condition while retaining closest-point Euclidean clearance when separated. The background minimum remains candidate-to-candidate only, as the released code supplies the filtered `adv_idx` set to both collision losses; candidate-to-frozen-background contacts remain diagnostics. The released repository's squared-center fallback is no longer canonical because its bounding-box function is unimplemented and contradicts both the paper and its KING source. Weights remain `1/5/20`, and `tau=1.25` is now metre-valued as intended. New artifacts use schema v3 and record `signed_oriented_box_distance_meters`; prior artifacts must be regenerated before comparison.
- Adversary-adversary collisions (updated 2026-09-09): the signed-box background term becomes active whenever the closest candidate boxes are within 1.25 m and penalizes overlap, instead of remaining saturated until centres are unrealistically close. The preceding squared-center implementation saturated in 61.1% of NuPlan iterations and permitted background collisions in 54% of C replays; those measurements are historical and must not be attributed to the box-distance loss. Road cost follows the paper's reduction `(1/T) sum_t sum_agents sum_4corners potential`, masking invalid samples and retaining absolute cost without baseline subtraction. We retain a three-sigma unit-mass convolution, bilinear interpolation, correct x/y indexing, and out-of-map padding rather than copying the released code's defective 32-pixel crop. The current tree has no road deadband or baseline subtraction; the following two bullets preserve rejected ablations only. Current weights are `1/5/20`.
- Road-term corner deadband (2026-09-09, measured and NOT adopted): a candidate fix scored `relu(potential - 0.01)` per corner. It is not in the tree; the finding about Adam below is why it was tried and is retained on its own merits. Adam's per-element step is `lr * m_hat/(sqrt(v_hat) + eps)`; `eps = 1e-8` is the only part that does not scale with the loss weight, so above that floor the weight cancels exactly and has *no* effect, while at or below it the step becomes linear in the gradient. Measured on map 0 with the road term alone over weights 0.2 / 20 / 2000 / 200000: agent 79 (per-element `g` about `3.7e-05`, far above the floor throughout) moves 10.95 / 10.13 / 10.22 / 10.20 m - a millionfold weight change with no effect - against 0.38 m at weight 0; agent 52 (per-element `g` about `8.5e-09`, sitting *at* the floor) moves 0.18 / 0.49 / 4.22 / 4.70 m. So the term is not binary, but **the weight cannot modulate how hard it pushes an agent meaningfully engaged with it**: lowering the weight does nothing until the gradient drops below `eps`, at which point the term collapses to inert. The only available control is the term's *support*. The convolved kernel is truncated at three sigma and so already has finite support (2 px = 2 m at the WOD 1.0 m raster); the 0.01 deadband halves it to about one pixel. Note the agents involved are *not* far from road edges - nonzero potential requires being inside that support, and agent 79's worst corner sits 2 px from a genuine off-road region, not a rasterization hole. The pathology is that Adam converts the gentle nudge such proximity should produce into a maximum-speed shove. The released code uses the same optimizer (`optax.adam`, default `eps=1e-8`) and inherits the property but never exercises it: its deviation term is identically zero under the `cost.py:96` crop bug, so this is ours alone, reached only because our road term works.

- Road-term ablation and the rejected reference subtraction (2026-09-09): a second candidate fix subtracted each corner's *baseline* potential, so that raster false negatives - logged vehicles standing on parking, driveway and unmapped shoulder pixels, e.g. map 2 agent 43 at mean potential 2.91 in the log while drawing a road gradient of 278 against the ego term - would not be penalized as infractions. Four full 100-scenario WOD runs isolate the two components (success / introduced off-road / background collision / median non-adversary candidate displacement / share of those past 1 m): neither 88, 46.0%, 63.0%, 0.738 m, 45.1%; deadband only 87, 40.0%, 53.0%, 0.365 m, 34.9%; reference only 88, 29.0%, 31.0%, 0.166 m, 5.4%; both 87, 29.0%, 30.0%, 0.158 m, 3.6%. Reference subtraction accounts for essentially the whole improvement and the deadband adds almost nothing on top of it. **Both were rejected at the user's direction on 2026-09-09 and neither is in the tree**, so the road term is byte-identical to its pre-2026-09-09 form. Record the ablation so the declined trade stays explicit: retaining the raster's false negatives as real cost is what those rows were buying back. Revisiting this means either accepting a baseline-relative road cost or fixing the drivable-area raster so its false negatives disappear at the source. Note these four runs predate the signed-box collision loss and the 0.001 learning rate, so their absolute rates are not comparable to current numbers.

- Optimizer learning rate (2026-09-09): all nine generation profiles use `learning_rate: 0.001`; `regents_wod_motion_val`, `_pdm` and `_policy` moved down from `0.005` at the user's direction. A 2x2 over collision metric and learning rate on the 100-scenario WOD cohort (success / introduced off-road / background collision / mean iterations to stop / mean per-element `|delta action|`): squared-centre at 0.005 gives 87, 40.0%, 53.0%, 34.8, 0.0369; squared-centre at 0.001 gives 81, 29.0%, 55.0%, 95.4, 0.0325; signed box at 0.005 gives 78, 29.0%, 51.0%, 74.6, 0.0447; signed box at 0.001 gives 75, 6.0%, 39.0%, 138.9, 0.0316. Each change alone removes 11 points of off-road; together they remove 34 - a +12-point interaction, not an additive effect. The two act on different things: signed box distance lets the ego term reach its target at *contact* (zero) instead of at centre coincidence, so the manoeuvre being optimized toward is itself less extreme, while the smaller step reduces overshoot in approaching it. Neither suffices alone - the box loss at 0.005 has the *highest* action deviation of the four (0.0447) and only pays off once the step is small enough to exploit the nearer target. Displacement is not the mediating variable: `early_stop_on_collision` means a lower rate simply runs more iterations (138.9 against 34.8), so bystander median displacement is roughly unchanged (0.365 m -> 0.813 m) and it is the gentler per-element action perturbation that collapses off-road, which is a threshold event. Costs across both changes: success 87 -> 75, with 13 `iteration_limit` rejections that are budget exhaustion rather than failure, and cumulative optimization 1247s -> 3039s. Raising `iteration_count` above 500 is the untested lever for recovering those.

- Background-collision loss scope (2026-09-09): the residual background-collision rate is dominated by pairs the loss cannot see, so it is not evidence against the box metric. Decomposing the 96 eligible WOD scenarios by which pair actually overlaps in the C replay: candidate-to-candidate only 4 (4.2%), candidate-to-frozen-replay only 36 (37.5%), both 11 (11.5%), none 45 (46.9%) - 47 of 51 flagged scenarios (92.2%) involve a candidate-to-frozen pair, for which `adv_col` has no term at any weight or metric. Separately, the term reduces by a single `min` over all pairs and all timesteps, shaping exactly one pair-timestep per iterate out of 6,075 cohort pairs, against the road term's `sum` which shapes all 25,665 units inside its support at once. At the final iterate only 40 of 6,075 candidate pairs (0.66%) overlap, so the metric was never the binding constraint on this rate. Widening the pair set to candidate-to-frozen is the only change that reaches the other 92%, and the map-8 trial recorded above shows it is not free.

- KING provenance audit (2026-09-09): the upstream KING repository (`king/`, `autonomousvision/king`) confirms that its collision cost computes oriented-box clearance in metres and applies the `1.25` threshold directly to that metric. ReGentS replaced the box-distance function with `pass` and used squared centre distance instead. PufferDrive now restores the paper/KING geometry with exact signed box distance while retaining ReGentS's weight of `5.0`; the sign additionally measures penetration depth. KING's road implementation remains rejected as a model for the local road loss because it uses a wider kernel and hardcoded 2x5 m boxes, while its working crop only serves as evidence that ReGentS's map-origin crop was a porting defect. KING also reports out-of-bounds outcomes separately rather than enforcing them as acceptance gates, consistent with the local diagnostics.
- Deviation-term audit (2026-09-07): the released deviation term never fires, so its coefficient carries no parity constraint. `cost.py:96` crops with `jnp.minimum(x_center - cropsize//2, 0)`, which is at most zero, and `dynamic_slice` clamps a negative start to zero, so every agent is scored against the same 32x32 patch at the map's origin corner; the map is also built `[y, x]` by `meshgrid`/`lax.map` but sliced `(x_center, y_center)`. The Gaussian therefore evaluates hundreds of metres from the agent and returns zero. Released ReGentS is effectively `ego_col + 5*adv_col`. Measured on scenario 0 with our working term at weight 10 versus weight 0: ego cost 25.72 -> 34.89 (failed) versus 25.72 -> 13.47 (succeeded), and the non-argmin agent 1 moved 14.58 m versus 0.19 m. The road term is therefore ours to validate and tune, not to match.
- Drivable-area raster (2026-09-07): build the surface from road-edge polylines (`ROAD_EDGE_UNKNOWN/BOUNDARY/MEDIAN`, newly exported as `binding.ROAD_TYPE_ROAD_EDGE_*`) with the reference signed-distance test, joined with the previous half-lane-width centerline corridor. Two corrections were needed. The export preserves no edge winding, unlike the reference dataset: on map 0, 737 edge points face their nearest lane negatively and 337 positively, whole polylines disagreeing, so each polyline is oriented by majority vote against the nearest lane centerline before the sign test runs unchanged. The nearest-point test then still mislabels wedges where two polylines meet, which alone left the map-0 ego off-road for 89% of its logged positions, so the lane corridor is unioned in: a mapped centerline is drivable by construction and repairs exactly those wedges. Across the 50 `regents_nuplan` maps the logged ego's road cost is now a median 0.05 of a 404 per-agent maximum (mean 7.54, max 46.42), moving candidates a median 0.00, and only 5 parked candidates sit fully off the road surface; raster build costs a mean 1.9 s per map. A map without road edges now aborts rather than falling back to the corridor alone. The historical 50-scenario rerun used the then-current `1/20/10` weights and raw time-summed road cost: generation success 40% -> 56%, off-road 14% -> 8%, `iteration_limit` failures 22 -> 14, background collisions 54% -> 62% (the saturated term still shapes nothing), C/torch parity unchanged at 3.4e-05, mean optimization 38.9 s per scenario against 29.4 s. Those measurements predate the paper time normalization and are not directly comparable. Scenario 0 still failed because its 100-transition window held a stationary ego, which is a horizon question, not a road-cost one.
- Deviation kernel normalization (2026-09-07): the convolution kernel carries unit mass, so a fully out-of-bounds corner costs exactly one at any raster resolution. The released amplitude has neither discrete mass normalization nor a pixel-area factor, which makes its potential scale with the inverse square of the resolution: a saturated corner is 1.290 at the reference's 1.0 m default and 5.011 at our 0.5 m raster. Since the released term never evaluates at the sampled position, that scale is not worth reproducing.
- Steering now defaults to curvature with a 0.5 post-Adam update scale. Divergence cancels only the applied steering update while preserving raw gradients and Adam moments. Projection follows scaling/cancellation. Curvature is the only parameterization; the wheel-angle mode was removed. Acceleration remains normalized and all PufferDrive physical limits remain in force. Historical sweeps below predate these loss/update changes.
- Stopping/result selection (2026-09-05): follow the released ReGentS optimizer by stopping on any valid candidate/ego overlap (including iteration zero) and returning the current iterate, or the last evaluated iterate at the update limit. Background collisions and off-road events are diagnostics, not acceptance gates. C replay still verifies trajectory parity and a new actionable ego collision; other infractions do not invalidate success. The collision-stop override remains available; the patience override was removed. Loss geometry, weights, filters, and frozen-ego dynamics are unchanged. We evaluate the final Adam update, unlike the reference's inner loop.
- Legacy artifact fields `best_iteration` and `*_rejection_count` now mean returned iteration and counts of iterates with new infractions, respectively. They no longer imply selection or rejection; artifacts identify the stopping policy explicitly. Prior acceptance results below used the former strict feasibility policy and are not directly comparable.
- State is `[batch, agent, time, feature]`: centered `x/y`, wrapped heading, signed speed, and steering angle. Action is `[batch, agent, time - 1, 2]`: normalized acceleration and target steering in `[-1, 1]`.
- Preserve stable agent identity, one documented coordinate frame, type, dimensions, wheelbase, maximum speed, SDC and validity masks, scenario ID, timestep, and map transform. Transition validity is `valid[t] & valid[t + 1]`; mask invalid values rather than repairing them.
- Validate external scenario data, tensor shapes/ranges, and artifact schemas before use. Controller routing remains native through `resolve_agent_controller()`; do not add a Python controller state machine.
- Logged/Torch speed is longitudinal velocity projected onto heading. C state uses speed magnitude signed by heading agreement. Compare speed/steering only after injection, compare position/heading only while jointly valid, exclude the shared initial state from scoring, and stop at the first C collision response.
- Judge optimized C events relative to a baseline C rollout so logged overlaps and raster errors are not attributed to optimization.
- Torch ego-collision baseline subtraction remains a follow-up: `_first_ego_collision` currently scans absolute candidate/ego contacts, while C excludes any collision pair observed anywhere in its baseline rollout. The intended matching change is to compute the baseline candidate/ego pair signature from `reference_boxes` once and ignore those candidate rows when finding the first optimized contact. Until then, the fidelity gate bounds candidate reconstruction drift in WOD optimization, but Torch's collision verdict is not independently protected from every baseline overlap artifact.
- The ego reacts inside the optimization loop, not around it. `ReGentSOptimizationConfig.ego_refresh_interval` re-rolls the ego in C every that many Adam updates via the `ego_rollout_fn` callback (`rollout.make_c_ego_rollout` installs the current adversary plan, captures the C rollout, then clears the plan); Adam moments and the action parameter persist across a refresh. This matches the reference, which re-simulates the ego policy on every gradient step under `torch.no_grad` (`ReGentS/method/optim_scenario.py:49`, `ReGentS/simulation.py:58`). `ego_refresh_interval: 0` keeps the caller's captured ego for the whole run and is bit-identical to the pre-refresh loop; it is the setting for log-replay egos, which cannot answer the adversary.
- A run-ending ego collision must be confirmed against a fresh ego. A contact found while the ego is stale forces a refresh and re-evaluates the same iterate, costing one extra forward pass; non-terminal contacts stay diagnostics and trigger no rollout. `iteration_count` counts Adam updates only, while `cost_history` also carries those recheck passes.
- `maximum_outer_iterations` and the re-freeze loop around a complete optimization are gone: the inner refresh subsumes them. `run_reactive_idm_generation` now runs one optimization and one C verification replay, and reports `ego_refresh_count` where artifacts and the metrics CSV carried `outer_iteration_count`.
- No gradient crosses C or the ego controller.
- Artifacts carry schema/version, dataset/scenario identity, exact config and map hash, masks, initial/optimized actions, Torch/C trajectories, controller actions, metadata, and metrics. Writes are atomic and pickle-free; loads reject unknown or inconsistent data.
- Logged and adversarial HTML replays label every post-filter adversary candidate. Ordinary `ADV` candidates render in dark yellow; the candidate supplying the final hard-min ego-collision loss renders in magenta, is labeled `LOSS ADV`, and is printed in scenario metadata. The selected adversary remains separate metadata for outcome attribution.
- Replay gallery indices expose `No candidate` and `Iteration limit` filters, an `IDM reconstruction collisions` filter derived from C baseline ego collision pairs, and a human-readable failure-reason badge on failed replays. This identifies candidate coverage, exhausted optimization budgets, baseline IDM contacts, and other recorded failure causes independently of collisions introduced by optimized adversary actions.
- Unconfirmed-collision reasons (2026-09-08): the single reason `c_did_not_confirm_actionable_ego_collision` is replaced by `ego_collision_present_in_baseline`, `ego_collision_with_other_agent`, and `no_ego_collision_in_replay`. All three mean parity held and Torch found a collision that C did not credit to the selected adversary, but they call for different work, and the old name both framed C as second-guessing Torch and hid which case applied. On the 100-scenario `regents_wod_motion_val_policy` run, all 33 of these were `ego_collision_present_in_baseline`: the policy ego already collides in the unmodified logged scene in 50 of 96 eligible scenarios (52.1%), so an adversary that drives it into the same agent has that pair subtracted as pre-existing. Note that pair subtraction ignores timestep, so a genuine adversarial collision with an agent the ego already hit later in the baseline is masked; this is the C-side counterpart of the Torch baseline-subtraction follow-up recorded above.
- Jerk ego / classic injection (2026-09-08): `move_dynamics` integrates the classic bicycle model whenever `use_regents_action` is set, whatever `env->dynamics_model` is, and `regents_set_action_plan` no longer requires a classic env. This exists because `pufferlib/ocean/torch.py` sizes a discrete actor head from the env's dynamics model - 4x3 jerk classes against 7x9 classic - so the available checkpoints, whose `actor_head.2.weight` is `(12, 256)`, cannot be instantiated against a classic env at all. The two paths never share an agent: injection is restricted to replay-controlled non-ego vehicles, while the ego is the only active agent, so Torch keeps modelling exactly what C does for adversaries. Measured on the pinned map-8 fixture, a jerk env reproduces the classic env's optimized actions bit for bit and stays inside the `5e-4` parity gate; across the first eight NuPlan maps at 30 updates the worst policy-ego parity error was `4.96e-5`. `dt` is unchanged at 0.1, which is already what `benchmark.yaml` evaluates these dt=0.3-trained checkpoints at.
- Policy ego determinism (2026-09-08): a policy ego loads on CPU in float32 and selects actions with `mean` or `mode` only; `sample` is rejected, because an ego refresh inside the Adam loop must reproduce across runs and across spawn workers. Speed is not the reason - a single-agent forward pass is dispatch-bound, so CPU, CUDA, and the two selection modes are all within noise, while CUDA at batch 1 across 24 workers reintroduces the batch-shape numerics risk for no gain. The real cost is `ego_refresh_interval`: a refresh is a full-horizon C rollout plus one forward pass per step, so policy profiles default to 10 rather than 1. `regents_nuplan_policy` also zeroes `obs_dropout_*`, `partner_blindness_*`, and `phantom_braking_*`, which otherwise inherit non-zero training defaults. These are scoped to the policy generation rather than the shared env block on purpose: `sample_erratic_flags` runs only for active agents and short-circuits before drawing when a probability is zero, so zeroing them shifts the RNG stream and would change existing IDM and replay results. Two identical policy-ego runs of the same scenario produce bit-identical optimized actions and C states.
- Ego refresh interval unified to 1 (2026-09-09): every generation profile now re-rolls the ego on every Adam update, matching the reference implementation, which re-simulates the ego on each gradient step. This reverses the earlier cost argument for 10, which assumed the C rollout dominated. Measured on the PDM smoke profile, interval 1 against 10 costs 32.7 s against 21.2 s of wall time for 10x the rollouts (500 refreshes against 50 on the scenario that ran to the update limit), because Torch optimization, not the C rollout, is the bottleneck; success and C/Torch parity were unchanged at 1/2 and `1.144e-05`. Interval 1 also makes the stale-ego recheck nearly free, since a contact is almost always found against a fresh ego. `regents_nuplan` keeps a log-replay ego and so still runs at an effective 0: `run_reactive_generation` coerces the interval to 0 whenever `sdc_controller` is replay, because a refresh would only re-derive the captured trajectory. Verified: the replay profile reports `ego_refresh_count=0` with the config asking for 1, and does not error on the `ego_refresh_interval requires an ego_rollout_fn` guard. The two policy profiles accept the full inference bill deliberately.
- PDM and corridor-IDM egos (2026-09-08): `pdm` and `corridor_idm` join `idm`, `replay`, and `policy` as ReGentS ego controllers. Both are native C controllers, so they need no ego action provider and no Python state machine; the change is four allowlists (`optimizer.SUPPORTED_SDC_CONTROLLERS`, `optimizer.EGO_TRAJECTORY_SOURCES` with the new `c_pdm`/`c_corridor_idm` sources, `adapter.export_drive_scenarios`'s controller check, and `evaluation.EVALUATION_EGO_CONTROLLERS`) plus the `regents_nuplan_pdm` and `regents_nuplan_corridor_idm` generation profiles. Both refresh at interval 1. Generated sets stay non-neutral and PDM is the strongest ego measured so far: on a three-scenario NuPlan probe, generation succeeded 3/3 against idm and corridor_idm but 2/3 against PDM, the miss being `iteration_limit` rather than a failure; cross-evaluating the IDM-targeted set reproduced 3/3 ego collisions under IDM, 1/3 under corridor_idm, and 0/3 under PDM. C/Torch parity is unaffected at a worst `1.34e-05`. Adversary injection remains restricted to replay-controlled non-ego vehicles, so the ego controller choice never changes what Torch models.
- Ego controller identity (2026-09-08): a generated set is not controller-neutral, so `ReactiveGenerationResult.ego_source` records the controller, artifacts carry it as `ego_controller`, the metrics CSV carries an `ego_controller` column, and the resolved `ego_policy` block - including the checkpoint's SHA-256, since a path is not an identity - participates in `source_configuration_hash`.
- Baseline-relative event attribution now lives in one function, `rollout.baseline_relative_events`. Generation replay and artifact-set evaluation both call it, so the definition of ego, actionable, and background collision and of introduced off-road cannot fork between the two.
- Captured ReGentS HTML omits observations by default, including the ego observation. A generation may explicitly opt in with `capture_observations: true`; this is valid only when HTML frames are also captured. Replay `active_count` remains the single controlled ego and never derives from the rollout horizon.

### Action-space decision

Reference ReGentS/Waymax uses raw acceleration (`+-6.0 m/s^2`) and instantaneous curvature (`+-0.3 1/m`), with a `0.6 m/s` inverse-dynamics steering guard. Its KING ego also writes PID throttle/steer into those physical-model slots. PufferDrive uses normalized actions over `+-4.0 m/s^2` and a `+-0.667 rad` target wheel angle rate-limited to `0.6 rad/s`.

`waymax_actions.py` provides differentiable conversion using

    curvature = cos(atan(rear_axle_ratio * tan(wheel_angle))) * tan(wheel_angle) / wheelbase

and its closed-form inverse. Reference authority exceeds PufferDrive authority: the latter reaches about `0.735 / wheelbase` curvature. Conversion therefore clamps unreachable values and reports saturation. Converted steering remains a rate-limited target, so it does not reproduce the requested yaw rate on the first step.

`ReGentSOptimizationConfig.steering_parameterization` selects:

- `wheel_angle`: normalized target angle with `steering_update_scale=0.5`.
- `curvature` (default): curvature in `1/m`, clamped per agent to `+-0.735 / wheelbase`, converted at rollout, with `curvature_steering_update_scale=0.5`.

Adam and post-update front-divergence cancellation operate on the selected parameter; moments are preserved. Frozen entries are copied verbatim from the post-conversion baseline. Artifact `initial_actions` and `optimized_actions` always remain normalized simulator actions, so downstream replay is parameterization-independent. Curvature round-trip error is about `1e-7` at iteration zero, so the curvature parameter is projected to `(1 - 1e-6)` of the achievable limit, before the first forward pass as well as after every Adam step: projecting onto the limit itself round trips, in float32, to a normalized wheel angle one ulp outside the action box for about 13% of wheelbases, which the C injector rejects.

A 12-map NuPlan comparison (seeds `42..53`, 50 transitions, 200 iterations, `lr=1e-3`; two filtered) tied at `7/10` successes with no safety rejections. Peak steering was `18.7` vs `19.4` degrees; curvature took 58 vs 45 iterations per success. This supports transfer of the reference scale but not changing the default; wall times were not comparable.

### Bounding-box collision loss (adopted 2026-09-09)

The paper defines the background-agent regularizer inherited from KING as

    C_adv_col(s) = -min_{i != j, i,j in backgrounds, k in [0,T-1]} min(tau, d_BB(i,j,k))

where `d_BB` is the closest-point distance between oriented bounding polygons. The prose calls it Euclidean while the collision condition uses `d_BB <= 0`; PufferDrive resolves that ambiguity with signed oriented-box distance in meters: it equals closest-point distance while separated and becomes negative under penetration. The paper uses one global hard minimum, so only the closest pair/timestep receives a gradient. This sparse gradient is paper-faithful, not an implementation accident.

The released `ReGentS/cost.py` is not the authority for geometry: its bounding-box distance function is unimplemented and its default path uses squared center distance with `tau**2`. It does confirm removal of self/duplicate pairs, truncation before negation, weights `5.0` with `tau=1.25`, and that the filtered `adv_idx` is the agent set supplied to both collision costs.

The canonical PufferDrive loss therefore uses post-filter candidate-to-candidate pairs, matching the released ReGentS method. Candidate-to-frozen-background contacts remain part of baseline-relative diagnostics, not the differentiable paper loss or an acceptance gate. A trial that widened the differentiable pair set made all 30 map-8 iterates off-road and removed the established collision, so wider pair scope is experimental rather than canonical.

## Constraints on future work

1. **Filter yield:** the historical overlap filter rejected `13/16`; the reference filter no longer excludes logged overlaps. Re-measure yield with full-log selection and report the optimization horizon separately, including candidates that enter after it.
2. **Drivable raster/loss:** centerline tubes under-cover NuPlan. Current loss uses the reference sum and absolute potential as specified above; raster resolution now affects its scale. Do not copy the reference crop literally: it uses `minimum(..., 0)` and x/y indices in `[y, x]` order. Sampled NuPlan edge-side conversions marked 22–58% of logged vehicle centers off-road because edge direction lacks Waymo's inside/outside convention. Drivable topology remains an independent limitation.
3. **Adversary selection/loss:** the paper uses hard minima for both ego collision induction and background collision avoidance. The ego term sent gradients to one candidate without argmin switching; the background term likewise exposes only one candidate pair/timestep. If joint optimization remains poor after the canonical loss is fully instrumented, compare one job per candidate and an explicitly non-paper dense pairwise surrogate rather than silently changing the canonical loss.
4. **Optimizer scale:** use curvature with reference steering scale 0.5 by default. Earlier wheel-angle sweeps used different losses and acceptance rules and do not establish suitable settings for the current objective.
5. **Regression invariants:** retain the straight-through signed-speed derivative at zero, per-agent reset before validity exits, separate front-bearing (`pi/8`) and yaw (`pi/2`) windows, and post-Adam steering scaling/clamping. The reset fix reduced worst parity error from `67.118` to `3.815e-5`.
6. **Full horizon:** the 200-transition/20-second run did not complete. Do not extrapolate parity, yield, runtime, or success beyond tested 16- and 50-transition horizons.

### Scenario batching, as measured when it existed

`optimize_frozen_ego_scenarios` runs any number of scenarios in one Adam loop;
`collate_scenarios` pads them to a shared agent and time count. Generation schedules
one batch per pool task via `batch_size`, ordering scenarios by agent count first.
Capture and C replay stay per-Drive, so no C contract changed.

**Correctness.** Batch size 1 reproduces the previous implementation exactly. Across a
240-scenario NuPlan run, batch 2 matched batch 1 on 239 of 240 scenarios; the one
difference was a `collision_timestep` of 82 against 83, with identical success,
adversary, and infraction verdicts. Scenarios stay independent because each loss reads
only its own actions, so the summed batch loss gives each row the gradient it would get
alone; a stopped scenario is masked out and its parameters restored after each step.

**Measured effect.** Batching removes per-iteration Python and dispatch overhead
(`_compose_rollout` is 30.8 ms of a ~67 ms iteration) but raises each worker's working
set. Those pull in opposite directions:

| setting | result |
| --- | --- |
| 1 worker, 8 scenarios, 100 iterations | 99 s at batch 1, 73 s at batch 8 (1.36x faster) |
| 24 workers, 240 scenarios, 100 iterations | 313 s at batch 1, 449 s at batch 2 (1.43x slower) |
| in-worker CPU, same 240 scenarios | 6973 s at batch 1, 8888 s at batch 2 (+27%) |

The regression is contention, not scheduling: per-scenario CPU time itself rises once 24
workers compete. `batch_size` therefore defaults to 1, which is the fastest setting for a
24-worker run on this machine; raise it only when workers sit well below core count.

An earlier synthetic benchmark predicted 2.09x. It was wrong twice over: it replicated one
scenario, so every batch member shared an agent count and a drivable-area raster. Real
agent counts run from 3 to 326, and padding in file order wastes 33% of the work at batch
2 and 54% at batch 8. Agent-count ordering recovers that to 96% and 84%, and is why
`_agent_count_ordered_batches` exists, but it does not recover the contention cost.

Two levers remain if batching is wanted at full worker count. `_background_collision_signature`
costs 9.8 ms per iteration and grows with the square of the background agent count, which is
what makes large scenes expensive to hold in a batch. Batches also run until every member
stops, worth about 77% efficiency at batch 8 given the observed iteration spread (min 1,
median 501, p75 501). Neither is addressed.
